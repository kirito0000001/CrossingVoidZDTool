# 对局内头像固定槽位设计

## 目标

St2 的“对局内头像”固定需要四张图片。界面需要明确区分四张图片的用途，同时保持为一个素材区，避免拆成四个纵向素材行。

固定映射如下：

| 索引 | 槽位名称 | 现有文件名 |
| --- | --- | --- |
| 1 | 1P主战 | `{角色编号}-BattleAvatar-01.png` |
| 2 | 1P护援 | `{角色编号}-BattleAvatar-02.png` |
| 3 | 2P主战 | `{角色编号}-BattleAvatar-03.png` |
| 4 | 2P护援 | `{角色编号}-BattleAvatar-04.png` |

现有文件不迁移、不重命名。工具根据文件索引显示槽位身份，保持与既有数据和 Unreal 同步流程兼容。

## 界面设计

“对局内头像”继续作为一个 St2 素材区。素材区内部按玩家分为 `1P` 和 `2P` 两组，每组横向排列“主战”和“护援”两个固定槽位：

```text
1P  [主战] [护援]    2P  [主战] [护援]
```

桌面宽度足够时两组处于同一行。窗口较窄时，`1P` 和 `2P` 两组整体换行，最多形成两行，不把四个槽位分别拆成四行。

每个槽位始终存在，并显示：

- 槽位名称，例如“1P主战”。
- 当前图片预览；缺失时显示空状态。
- 合规、尺寸错误或缺失状态。
- 对应槽位的导入入口。
- 已有图片沿用右键“修复”和“重新导入”。

其他基础素材继续使用现有通用素材卡布局，不受此次调整影响。

## 数据结构

为界面增加固定槽位模型，至少包含：

- 槽位索引。
- 玩家标签 `1P` 或 `2P`。
- 角色标签“主战”或“护援”。
- 对应的 `BaseMaterialItem`，允许为空。
- 面向绑定的预览、状态和是否缺失属性。

`BaseMaterialSection` 在种类为 `BattleAvatar` 时生成四个槽位，并按索引匹配现有素材。其他素材区不生成固定槽位。

## 导入与保存

从某个空槽位导入时，裁剪流程保持不变，目标尺寸仍为 `566x325`，但保存操作显式使用该槽位索引，不再仅依赖“下一个编号”。

从已有槽位重新导入或修复时，继续覆盖同一索引文件。操作完成后刷新 St2，图片回到原槽位。

顶部通用新增按钮对“对局内头像”的行为调整为定位并填充第一个缺失槽位；四个槽位均已有图片时不再生成 `-05`。其他可多张素材仍沿用现有追加编号行为。

## 兼容与异常处理

- 已有 `-01` 至 `-04` 文件直接映射到四个槽位。
- 若目录中存在 `-05` 或更大索引，保留磁盘文件，不自动删除；在素材区状态中提示存在额外文件，避免静默丢失数据。
- 图片损坏或尺寸不合规时仍显示在所属槽位，并保留现有修复入口。
- 单个索引存在多个可识别文件时，沿用当前排序选择逻辑并报告异常，不自动覆盖多余文件。

## 验证

- 服务层测试四个索引与槽位名称的固定映射。
- 服务层测试指定槽位导入会写入正确文件名，且不会生成 `BattleAvatar-05`。
- 测试现有四张图片无需迁移即可正确进入槽位。
- 测试缺图、尺寸错误和额外文件的状态统计。
- 构建 Debug x64，打开 St2 验证宽窗口为一行两组、窄窗口最多两行，以及四个槽位的导入、修复和重新导入流程。

## 不在范围内

- 不修改四张图片的目标尺寸。
- 不修改 Unreal 工程或 Unreal 侧资源。
- 不迁移或重命名现有素材文件。
- 不调整其他基础素材的卡片布局和文件规则。
