# 第二步「同步素材」（规整 + 素材同步合并）—— 设计

> 依据晓桀 2026-09-24 的三条决定：
> **① 合并后就是第 2 步**（后面的步号跟着挪，方向是**最大解耦、前后不关联**）；
> **② 去掉自动检测** —— 只有他点才检测，且检测只含素材相关；
> **③ 每一步都不阻断同步** —— **「检查」会成为一个独立的阶段**，他以后专门设计。
>
> 补充：③ 原话说的是"检查**截断**"，随后更正为"检查**阶段**"。
> 差别很重要：不是给每一步装一道闸门，而是**把"检查"从各步的流程里拿出来、做成一个独立的阶段**。
> 所以本轮只做两件事：**把现有的门卸掉**，并且**不把检查塞进任何一步**；那个阶段长什么样、放在哪，留给他设计。
>
> 这份只写"怎么并、怎么挪、门怎么卸"，不写代码。**没有待定项。**

## 3. 去掉自动检测（②）

①「检测素材变化」（本步）；②「重新加载…」（各步）；③「依次检测后续步骤」。

## 5. 最大解耦：第 2 步要真的独立

合并**消掉**的耦合（旧第 3 步读旧第 2 步）：
- `CanExecutePublishChange` / `IsPublishSelectionReady` 读 `NormalizationItems` → **变成同一步内部** ✓
- `SelectionContentVisibility` 排除 `IsNormalizationWorkspace` → 这个标志**消失** ✓

**还剩一处必须在这轮解决**：`SelectionTreeRoots`（差异树）是**旧第 3 步与旧第 5/7 步共用一个槽位**，
靠 `_loadedPublishStep` 分归属。按 ①「前后不关联」，第 2 步不该再和别人共用一棵树。

**定案：给第 2 步一棵自己的树**（`MaterialSelectionTreeRoots` 之类）；
序列/特效**沿用现在的共享槽位，留待后面重构**（① 说了"后面的也会重构"，本轮的边界就是不把四步一起动）。

- 做法：把差异树那套（建 / 过滤 / 勾选 / 恢复 / 计数 / `SetSelectionTree` / `ApplyPublishFilter`）
  **参数化成"按步取树"**；
- 代价：这一处是本轮**唯一的机械改动**，但改完第 2 步就真的独立了；
- 边界：**不**顺手把第 4/6 步的树也拆了 —— 那是"后面的重构"，一次动四步风险成倍。

## 6. 你怎么测

1. **流程表**：6 行，第 2 行叫「同步素材」，没有「规整素材」。
2. **不自动检测**：进第 2 步 → **不发生任何虚幻进程活动**（日志里没有导出那条）；点「检测素材变化」才开始。
   切角色回来也一样，不会自己跑。
3. **规整与同步同屏**：规整段能选/清/标不需要；选完之后差异树里那条"待删除"从灰变可点
   （**原来要跨两步才成立的联动，现在同屏**）。
4. **没有规整项的角色**：面板直接是差异树，不空一块。
5. **不阻断**：故意留一项没规整 → 别的项照样能同步。
6. **重启**：规整决策还在（三级兜底那一路）。
7. **只跑一次导出**：点一次检测 → 日志里素材范围的导出只出现一遍。
