## 踩过的坑（别重复踩）

- **编译前先关程序**：工具箱 exe / 编辑器 DLL 被锁会报 MSB3027 / LNK 无法写入。
- **XAML 有静默崩溃先例**：XamlCompiler 返回 1、零诊断；改 XAML 必须单独一轮、立刻编译。
- **UHT 转出来的 Python 名字和 C++ 不一样**：`EnsureEffectSubUVSheetMaterial` → `ensure_effect_sub_uv_sheet_material`。
- **UE 5.8 差异**：`FString::Printf` 的 `MakeError` 之类同名模板会抢重载（我们的助手改名 `MakeErrorJson`）；
  `IAssetTools::DuplicateAsset` 只收 `UObject*`；`UMaterialEditingLibrary` 在 `MaterialEditor` 模块、`IPluginManager` 在 `Projects` 模块。
- **"先清后建"名单**：特效层的 `CanonicalAssetObjectPaths` 是清理的权威依据，**名单和生产必须同时改**（只改一边会留下删不掉的资产，或把刚建的删掉）。
- **别用 Click 测特效**（它没有特效层）；用 DefAtk。
- **别用 `Set-Content -Encoding UTF8` 批量改源码**（Windows PowerShell 5.1）：它会**加 UTF-8 BOM**，
  而这个仓库的 `.cs` 文件都没有 BOM → 整个文件头跟着进 diff（2026-09-27 踩过，已回退）。
- **改完源码核一下行尾**：这个仓库工作区是 **CRLF**（`core.autocrlf = true`，没有 `.gitattributes`），
  而某些编辑工具会把**整份文件写成 LF** —— `git status` 会警告
  `LF will be replaced by CRLF the next time Git touches it`（2026-09-27 踩过，6 个文件被写成 LF，
  已按字节补回 `\r`）。核对口径：统计文件里 `\n` 前面是不是都有 `\r`、以及头 3 字节有没有 BOM。
  要批量替换就用 `[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`，
  或者干脆走编辑器逐处改。

## 2026-09-27：特效落点去掉两层 + PSD「图层读取错误 -53」定案

晓桀两条：「特效多套了两层路径」「导出的 PSD 有报错，图层读取错误 -53」。

### 一、特效帧落点上移（去掉两层）

```
旧：ZDMaterial\<动作>\Effects\Effect\Frames\Misaka_Sk2_Effect_0001.png
新：ZDMaterial\<动作>\Effects\Misaka_Sk2_Effect_0001.png
```

`Effect`（层名）和 `Frames` 两层都是多余的 —— 层名本来就写在每个文件名里。

### 二、PSD 的「图层读取错误 -53」：组记录的**形状**差三处

拿晓桀给的「画世界导出的 5 图层组」样本逐条比（`PsdReader` 打出每条记录的通道数与附加块）：

| | 画世界 | 我们（修之前） | 结论 |
|---|---|---|---|
| 组壳层的通道数 | **4** | 0 | ✗ 必须 4（0×0 矩形 → 每个通道 2 字节 RLE 头） |
| `lsct` 数据长度 | **4** | 12 | ✗ 只写种类那 4 字节 |
| 附加块顺序 | `luni` → `lsct` | `lsct` → `luni` | ✗ 按它的来 |

三处都改齐之后，我们生成的组记录和它的样本**一模一样**（`底板PSD的组记录与画世界同形状` 用例钉住）。

> 这三处规范上都"允许多种写法"，但对方只吃一种 —— 属于典型的"能跑不算对，得和对方一致才算对"。

### 三、顺带修掉读侧一个真 bug：名字字段的 4 字节补齐没跳

`PsdReader` 读完图层名直接往下扫附加块，而名字字段是**补齐到 4 字节**的
（长度字节一起算）。带填充的名字（`参考 0001`、`</Layer group>`）会让附加块**整段读空或读歪** ——
以前没炸只是因为 `lsct` 恰好是我写在第一个块、而扫到的偏移偶尔还对得上。
现在按 `(nameLength + 1 + 3) / 4 * 4` 跳到边界再扫（和写侧同一个公式）。

## 2026-09-27：底板导出不再卡成无响应 + 图层组默认只留第 1 组可见

4. 隐藏位（`Flags & 0x02`）**照旧不看**：被关掉的组里照样可能有画好的特效，该收还是要收（见 `PsdLayerBitmap.Flags`）。

## 交接卡：特效这条链的现状（2026-09-27，给「优化特效导出」这个议题用）

### 整条链（从上到下）

1. **导出底板** —— 序列帧编辑器 →「导出 ▾」→ 导出底板。
   落 `D:\NewData\CrossingVoidZDProject\Export\<角色>\BasePlate\<动作>-2x\`：
   N 张 928×640 PNG + `frames.csv` + `<角色>_<动作>-2x.psd`。
   一格 = 1/动作FPS 秒，每格再切成 2 份 → 帧率翻倍、时长不变（10fps 动作 → 20fps）。
   下拉里还有一条**「导出底板（带特效）」**：落点、形状完全一样，只是组里 `特效` 层填的是
   已经画好的特效帧（没画过的帧留空层），方便在原稿上接着改；盘上已有那份 PSD 时会先弹一次覆盖确认。

### 体积参考（可能和「优化特效导出」有关）

真实 DefAtk（12 源帧 → 24 输出帧、928×640）导出的 PSD 是 **2823 KB**，
96 条记录 = 24 个组 ×（组底 + `原本帧` + `特效` + 组名）。
**这 96 条里只有 24 层 `原本帧` 带像素**（`特效` 是全透明、组底是 0×0），
所以体积基本就等于那 24 张 928×640 的 RLE 压缩结果。
要压体积，能砍的方向是"对照底图不进组（改成组外只留一张，或复用同一层）"，
代价是失去"展开一个组就能对着画"。
