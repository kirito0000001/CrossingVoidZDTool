## 一句话结论

**问题不是「没有架构」，是「有架构、但没有任何机制拦住代码偏离它」。**

`Docs/MvvmAndUxGuidelines.md`（367 行）早就写明了分层、MVVM 规则、命令链路，结尾还专门警告过「别把项目养成一个超大的 MainWindow.xaml.cs」。MVVM 的基础设施（`ObservableObject` / `RelayCommand` / `AsyncRelayCommand`）也早就写好了。

而实际代码：

| 规约怎么写的 | 代码实际怎样 |
|---|---|
| `Button → VM Command → Service → State → Binding` | `Command=` **0** 次，`Click=` **132** 次，事件处理器 **257** 个 |
| 异步命令用 `AsyncRelayCommand` | 实例化 **0** 次（132 行死代码） |
| MainWindow 只做外壳桥接 | MainWindow 分部 **11248 行**，含一个 **583 行的 `async void`** 业务编排 |
| 业务逻辑往 Service 走 | Services 层 16800 行，**整层 0 处日志出口**，约 90 处 `catch` 全静默 |

更关键的是：**回归测试把反模式固化成了断言**——73 处断言 MainWindow 源码文本，其中一条直接断言 `Click="XxxButton_Click"`，等于钉死了「不许改成 Command 绑定」。任何朝规约靠拢的改动都会先撞一片红。**这是漂移能持续的直接原因。**

### 3. 「失败语音进 Other」的根因找到了

`04-语音分类专项.md`：`UnrealProjectSyncService.cs:2948` 在决定语音分类时，**只要序列反推命中就直接采用，哪怕结果是 `Other`**，绝不回退到按名字识别。而反推只认 9 个动作码，标准动作表有 19 个——**DefAtk、Defence、Dodge、Idle、Move 等 10 个动作全部返回 `Other`**。

## 两个反复出现的模式

这两族都不是孤立 bug，是**缺少统一约定**的症状：

**路径/资产名大小写**（4 个实例）：第六步资产引用（已修）、第五步清理误删刚生成的资产、资产规整判定、导出脚本两处。
→ 缺一个「资产路径一律大小写不敏感比较」的公共函数。

**显示成功但实际没做成**（6 个实例）：蓝图保存、settings 损坏、陈旧结果文件、伪条目计数、顶层 succeeded 恒 True、第三步不读执行结果。
→ 缺 Services 层的日志出口和「失败必须上报」的纪律。

## 明确建议**不做**的事

| 不做 | 理由 |
|---|---|
| 拆多个 Page + Frame 导航 | 9 个页面共享一个 `ApplicationViewModel` 和大量交叉状态；12 个遮罩层是跨页的，`Frame` 里放不下；页面动画和滚动位置保持都围绕 Visibility 模型写的 |
| 引入 DI 容器 | 手写组合根 85 行已经清楚，容器只增加启动开销和 trimming 风险 |
| `{Binding}` 全量换 `{x:Bind}` | 528 处，单根 DataContext 下工作良好。只在**新写**的部分用 |

`MainWindow.xaml` 5522 行的替代解法：把 12 个遮罩层抽成 `Controls/*.xaml`，XAML 降到约 3300 行且**不动导航模型**。项目里已有先例 `SkillEditorControl.xaml`。
