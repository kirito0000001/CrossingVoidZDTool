### ✅ S1. 蓝图保存失败被吞掉，界面报「已写入 N 项、错误 0」

`Tools/UnrealBridge/apply_blueprint_setup.py:608`

```python
if touched_blueprint and _save_asset(blueprint_path):
    saved.append(blueprint_path)          # 没有 else，保存失败什么都不记
```

**这是我上一轮那个修复（`fbbf4bb`）的漏网。** 我修的是「写入报告说成功、复查却有差异」，但没覆盖「内存里写成功、包却没保存到磁盘」：

- 复查 `_scan()` 读的是**同进程内存里的 CDO**，值当然等于目标 → `STATUS_UNCHANGED`
- → `_reconcile_applied` 把它算进 `confirmed` → `succeeded = True`
- C# 侧 `MainWindow.UnrealSync.BlueprintSetup.cs:72` 只报 `AppliedStableIds.Count`，`SavedAssets` 为空**没人校验**

**触发**：资产被源码管理签出/只读、磁盘满、包被占用。
**后果**：离线 commandlet 模式下进程一退出改动全丢，用户看到「已写入并复查 N 项，剩余待写入 0 项」。
**修法**：`else: failures["bp"] = "蓝图保存失败"`，并让 `_reconcile_applied` 对 `touched_blueprint and not saved` 整体判错。同函数 `:602-606` 的技能写入失败已经会记 `failures`，照抄即可。

### ✅ S3. 角色数据写入不原子 —— 崩溃即整份消失

`Services/CharacterWorkspaceService.cs:779-789`

```csharp
private static void WriteAllTextAtomic(string path, string text)
{
    var tempPath = $"{path}.tmp";
    File.WriteAllText(tempPath, text, Encoding.UTF8);
    if (File.Exists(path)) { File.Delete(path); }   // ← 删和移之间崩溃 = 数据全没
    File.Move(tempPath, path);
}
```

名叫 atomic，实际是**删除再移动**。同仓 `CharacterToolboxDataService.cs:136` 的同名函数用的是正确写法（`File.Move(tempPath, path, overwrite: true)`），另外 8 处也是正确的——**唯独这一处**，而它写的正是角色的技能/BUFF/信息主数据。

临时名还是固定的 `$"{path}.tmp"`，并发保存会互相踩。

**同文件另两处**：
- `:644-647` `SaveMetadata` **连临时文件都没有**，直接 `File.WriteAllText`，写一半崩溃就是坏 JSON
- `:664-667` `ReadMetadata` 的 `catch { return null; }` —— 坏掉的 metadata 让角色**从角色台上直接消失**，无任何提示

`Services/SequenceFrameService.cs:1288-1291` + `:1262-1268`

```csharp
catch { continue; }                                            // 读失败当作"零引用"

if (!referenced.Contains(Path.GetFullPath(file))) { File.Delete(file); }
```

`PruneUnreferencedFrameFiles` 在每次删帧/重排/替换/插入后都跑（5 个调用点），紧接在 `SaveManifest` 之后。只要 `sequence.json` 这一刻读不到（杀软扫描刚写完的文件、被占用、上游非原子写留下的坏文件），该动作 `Frames/` 下的**用户帧图会被永久删除**，界面无提示。

### ◻ S7. 第五步清理旧资产按大小写敏感，会删掉刚同步出来的资产

`Tools/UnrealBridge/sync_character_sequences.py:497-500`

两个判据大小写语义相反：
- `paths` 来自同步**前**的真实拼写（`Defatk`）
- `new_paths` 是 `get_path_name()` 刚改名成的**规范拼写**（`DefAtk`）

**触发场景正是我上一轮修的那个**（老资产名与规范名只差大小写）；`_align_*_case` 函数的存在本身就证明这在真实工程里会发生。
**修法**：`new_packages` 与比较键统一 `.casefold()`。
